Tu ambiente de trabajo en Google Cloud

Al terminar tendrás un proyecto propio con presupuesto y una máquina virtual con MariaDB lista para la sesión 2. Los pasos 5 y 6 se ensayaron con una máquina real y las salidas de esta guía vienen de ese ensayo (las direcciones IP y los números de proyecto cambian en tu cuenta). Los pasos 1 a 4 se hacen en la consola y no se ensayaron con una cuenta nueva: los nombres de los menús pueden variar un poco; si un botón no aparece, busca la misma función con el buscador de la consola.

Antes de empezar

  • Una cuenta de Google y un navegador actualizado. No hace falta instalar nada en tu computadora: todo se hace desde la consola y Cloud Shell.
  • Un método de pago para activar la facturación. Si eres cliente nuevo, la prueba gratuita ofrece un crédito de bienvenida; verifica la elegibilidad, el monto y la vigencia en tu cuenta antes de aceptar.
  • Tiempo: 70 minutos. La instalación de MariaDB (paso 5) tarda unos 14 minutos y ocurre sola; mientras tanto explorarás la consola.
  • Convención de esta guía: TU_PROYECTO es el ID de tu proyecto (no el nombre). Sustitúyelo en los comandos.

Paso 1 · Crea tu proyecto y comprueba la facturación · 8 min

Dónde: Consola de Google Cloud (console.cloud.google.com) → selector de proyectos, arriba junto al logotipo → Proyecto nuevo.

Acción: Crea un proyecto con un nombre como big-data-curso. Anota el ID que aparece debajo del nombre (puede llevar números al final). Después abre el menú Facturación y confirma que el proyecto tiene una cuenta de facturación vinculada.

Salida esperada:

Nombre: big-data-curso
ID:     big-data-curso-123456      ← ejemplo; el tuyo será distinto
Facturación: vinculada

Comprueba: El selector de proyectos muestra tu proyecto y su ID, y en Facturación aparece vinculado a tu cuenta de pago.

Error frecuente y recuperación: Confundir el nombre con el ID: los comandos usan el ID. Si al crear recursos aparece «billing must be enabled», el proyecto no tiene facturación vinculada: vincúlala en Facturación y reintenta.

Paso 2 · Abre Cloud Shell y confirma tu identidad · 7 min

Dónde: Consola → icono de terminal Activar Cloud Shell (arriba a la derecha). Se abre una terminal en la parte inferior.

Acción: Comprueba con qué cuenta estás trabajando, fija tu proyecto y confirma que quedó seleccionado.

gcloud auth list
gcloud config set project TU_PROYECTO
gcloud config get-value project
pwd

Salida esperada:

Credentialed Accounts
ACTIVE  ACCOUNT
*       tu-correo@gmail.com

Updated property [core/project].
TU_PROYECTO
/home/tu_usuario

Comprueba: El comando get-value project imprime el ID de tu proyecto, igual al que viste en el paso 1.

Error frecuente y recuperación: Si imprime (unset) o el proyecto de otra persona, repite gcloud config set project TU_PROYECTO con tu ID. Si aparece «does not have permission», estás en una cuenta que no es dueña del proyecto: cambia de cuenta en la consola.

Paso 3 · Crea un presupuesto con alertas · 10 min

Dónde: Consola → menú Facturación → Presupuestos y alertas → Crear presupuesto.

Acción: Alcance: tu proyecto. Monto: una cifra baja que puedas permitirte (por ejemplo, 20 dólares). Umbrales: 50 %, 90 % y 100 %. Activa los correos de aviso. Recuerda: el presupuesto avisa, no apaga nada.

Referencia: documentación de presupuestos y alertas de Google Cloud. Paso de consola, no ensayado con una cuenta nueva.

gcloud billing projects describe TU_PROYECTO --format="value(billingEnabled)"

Salida esperada:

True

Comprueba: El presupuesto aparece en la lista con tu proyecto como alcance y el comando imprime True.

Error frecuente y recuperación: Si no ves «Crear presupuesto», tu cuenta no administra la cuenta de facturación: usa una cuenta de facturación propia o créala. Un presupuesto no impide el gasto: para frenarlo hay que detener o borrar recursos (paso 6).

Paso 4 · Activa Compute Engine · 5 min

Dónde: Cloud Shell, con el proyecto del paso 2.

Acción: Activa el servicio que permite crear máquinas virtuales. La primera vez puede tardar un minuto.

gcloud services enable compute.googleapis.com
gcloud services list --enabled --format="value(config.name)" | grep compute.googleapis.com

Salida esperada:

Operation "operations/acf.p2-123456789012-..." finished successfully.
compute.googleapis.com

Comprueba: La segunda línea de salida muestra compute.googleapis.com.

Error frecuente y recuperación: Si aparece «billing account for project … is not found», vuelve al paso 1 y vincula la facturación. Si pide autorizar, pulsa Autorizar.

Paso 5 · Crea la máquina con MariaDB · 25 min

Dónde: Cloud Shell (no desde dentro de la máquina).

Acción: Trae con git los scripts del curso, entra a la carpeta y ejecuta el script. No escribes los scripts a mano: ya están en el repositorio del curso. crear_firewall_y_instancia.sh crea la regla de firewall (si no existe) y la máquina mariadb-curso: e2-micro, Ubuntu 22.04, disco de 30 GB, zona us-central1-a. Al crearla le entrega startup-mariadb.sh, que se ejecuta dentro de la máquina al arrancar: instala MariaDB y crea el usuario del curso. Antes de ejecutar, lee los scripts en GitHub: recursos/mariadb ↗.

Qué hace cada opción de git clone: --depth 1 baja solo la versión más reciente, no todo el historial; --sparse con sparse-checkout set trae únicamente la carpeta recursos/mariadb (unos 0.5 MB) en lugar de todo el repositorio (unos 47 MB); --branch plan3 elige la rama del curso.

git clone --depth 1 --filter=blob:none --sparse --branch plan3 https://github.com/ChemaSarmiento/Big_Data_UP.git
cd Big_Data_UP
git sparse-checkout set recursos/mariadb
cd recursos/mariadb
ls
./crear_firewall_y_instancia.sh

Salida esperada, primera parte (git y listado):

Cloning into 'Big_Data_UP'...
README.md  crear_firewall_y_instancia.sh  startup-mariadb.sh  verificar_instalacion.sh

Salida esperada, segunda parte (el script):

Comprueba: El listado muestra los cuatro archivos. El comando termina con «Instancia creada» y la máquina aparece como RUNNING en Compute Engine. La base de datos estará lista cuando el registro de instalación diga «Instalación completa» (paso 6).

Error frecuente y recuperación: Con git: si aparece «destination path 'Big_Data_UP' already exists», ya lo clonaste; entra con cd Big_Data_UP/recursos/mariadb o borra la carpeta con rm -rf ~/Big_Data_UP y repite. Si el script responde «Permission denied», escribe chmod +x *.sh y vuelve a lanzarlo. Si dice que la instancia ya existe, usa otro nombre en el script o bórrala con gcloud compute instances delete mariadb-curso --zone=us-central1-a. Si aparece un error de cuota o de zona, cambia la zona (por ejemplo us-central1-b) en el script. Si «Instalación completa» no aparece tras 25 minutos, lee el registro completo con sudo cat /var/log/mariadb_install.log.

Mientras se instala (≈ 14 min): abre en la consola Compute Engine → Instancias de VM y encuentra mariadb-curso. Relaciona cada columna con lo que pidió el script: zona us-central1-a (la elegimos en la sesión), tipo e2-micro (≈ 1 GB de memoria), una IP externa, y la etiqueta de red mariadb-server a la que apunta la regla de firewall (Redes de VPC → Firewall). Cuando termines, pasa al paso 6.

Decisión didáctica: el puerto 3306 queda abierto a todo internet y el usuario y la contraseña son comunes. Es un entorno desechable con datos públicos de práctica; nunca repitas este patrón con datos reales. Si prefieres una versión menos expuesta del mismo ejercicio, ejecuta ./crear_firewall_y_instancia.sh 35.235.240.0/20 (rango de IAP) y conéctate por SSH como en el paso 6.

Paso 6 · Verifica, conéctate y detén la máquina · 15 min

Dónde: Cloud Shell.

Acción: Ejecuta verificar_instalacion.sh, que ya viene en la carpeta que clonaste: se conecta por SSH y revisa el registro de instalación, el puerto 3306 y el servicio. Espera a que el registro diga «Instalación completa» (la primera vez gcloud crea una llave SSH: si pide frase de paso, pulsa Enter dos veces). Después conéctate con el usuario del curso y ejecuta tu primera consulta. Al terminar, detén la máquina: un recurso detenido no cobra cómputo (su disco sí sigue existiendo).

# En la misma carpeta (Big_Data_UP/recursos/mariadb) y con la máquina ya creada:
# 1) Verifica: muestra el registro de instalación, si MariaDB escucha y el estado del servicio
./verificar_instalacion.sh

# 2) Conéctate con el usuario del curso y haz tu primera consulta
gcloud compute ssh mariadb-curso --zone=us-central1-a --quiet --command="mysql -u big_data_user -pExample123 -t -e \"SELECT VERSION() AS version, CURRENT_USER() AS usuario; SHOW DATABASES;\""

# 3) Detén la máquina para no gastar cómputo (se vuelve a encender con: gcloud compute instances start ...)
gcloud compute instances stop mariadb-curso --zone=us-central1-a
gcloud compute instances describe mariadb-curso --zone=us-central1-a --format="value(status)"

Comprueba: El comando 1 muestra «Instalación completa», MariaDB escuchando en el puerto 3306 y el servicio activo; el comando 2 muestra la versión 10.6 y las cuatro bases de datos del sistema; el comando 3 deja la máquina en TERMINATED. Para volver a trabajar: gcloud compute instances start mariadb-curso --zone=us-central1-a (la IP externa puede cambiar; SSH por nombre sigue funcionando).

Error frecuente y recuperación: Si aparece «Permission denied (publickey)», espera un minuto a que se propague la llave y repite con --quiet. Si «Instalación completa» no aparece, la instalación sigue: repite el comando 1 en unos minutos. Si MariaDB no responde, revisa sudo systemctl status mariadb --no-pager.

Cierre y costos

  • Proyecto con ID anotado y facturación vinculada.
  • Presupuesto con alertas al 50, 90 y 100 %.
  • Máquina mariadb-curso con MariaDB y el usuario del curso, que respondió una consulta; detenida al terminar.

Costo: el cómputo se cobra por tiempo encendido y el disco por GB mientras exista; según la documentación vigente, una e2-micro al mes y 30 GB de disco estándar en ciertas regiones de EE. UU. (incluida us-central1) entran en el cupo gratuito. Verifica las condiciones en tu cuenta. Detener frena el cómputo; no borra el disco.

Cierre de recursos: al terminar el curso borra lo que creaste: gcloud compute instances delete mariadb-curso --zone=us-central1-a y gcloud compute firewall-rules delete allow-mariadb-curso (comandos estándar de gcloud, no ensayados aquí). Cerrar la página no detiene recursos.

Lo que sigue: en la sesión 2 cargarás una base de ejemplo en esta misma máquina y aprenderás SQL.
