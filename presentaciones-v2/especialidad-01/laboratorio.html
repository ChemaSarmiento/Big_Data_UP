Un entorno identificable.
Una decisión propia.

Seis pasos de preparación en 55 minutos, seguidos de 30 minutos para plantear el proyecto de tu equipo. PROFECO es el ejemplo guiado; el proyecto final usa un dataset distinto por equipo.

Las acciones se realizan en tu consola, no desde esta página. La guía se contrastó con documentación el 5 de noviembre de 2026; todavía no se ha ensayado end-to-end en una cuenta GCP de clase. Si algo requiere un permiso que no tienes, registra la dependencia y usa el acceso autorizado del docente.

Antes de empezar

  • Cuenta Google, acceso a un proyecto de laboratorio y responsable de facturación identificado. Comprueba elegibilidad y crédito restante; una cuenta anterior puede no tener derecho a otra prueba.
  • Docente: prepara un acceso de respaldo, ubicación compatible para Storage/BigQuery y registro de fuentes candidatas distintas por equipo.
  • Parámetros del ejercicio: ID de proyecto verificado; región acordada (propuesta: us-central1 si está permitida); nombre de bucket único; destinatario de avisos; moneda y periodo de presupuesto.
  • No descargar datasets grandes en el portátil o el almacenamiento pequeño de Cloud Shell. Hoy se prepara el entorno, no se ingiere el archivo completo.

1. Identifica cuenta, proyecto y facturación · 5 min

Objetivo: saber dónde se crearán los recursos y quién responde por su uso.

  1. Abre Google Cloud Console y revisa la cuenta activa.
  2. En el selector superior, selecciona un proyecto de laboratorio autorizado o elige Nuevo proyecto. Usa un nombre reconocible del equipo y registra el ID que muestra la consola. El nombre visible y el ID no siempre coinciden.
  3. Abre Facturación para ese proyecto. Comprueba vínculo, estado del crédito y responsable. Si hay una organización, respeta la ubicación y permisos que indique el docente.

Comprueba: anota ID, responsable y estado de acceso en H1. No se espera que una cuenta nueva complete validaciones en cinco minutos.

Si falla: error al crear o vincular → revisar cuenta, permisos y elegibilidad con el docente. Si usas proyecto docente, márcalo como acceso autorizado. No es necesario cambiar a cuenta de pago para completar la práctica de clase.

2. Verifica el proyecto de la terminal · 8 min

Antes: tener el ID de proyecto comprobado. Abre Cloud Shell desde la consola; no es necesario instalar software en tu portátil.

Pega el siguiente comando de solo lectura:

gcloud config get-value project

Debes observar: el ID que seleccionaste en la consola. Guarda la salida sin secretos.

Si devuelve (unset) o un ID distinto: reemplaza el marcador por el ID que ya verificaste y ejecuta:

gcloud config set project ID_DE_TU_PROYECTO
gcloud config get-value project

El primer comando cambia la configuración de la CLI; no crea un proyecto. Si falla por acceso, vuelve a comprobar cuenta y permiso. No elijas un proyecto ajeno solo porque aparece en la lista.

3. Configura avisos y acuerda una acción · 12 min

Antes: responsable y permisos de presupuesto identificados.

  1. Abre Facturación → Presupuestos y alertas → Crear presupuesto. Nombre sugerido: curso-equipo-presupuesto.
  2. Restringe el alcance al proyecto del ejercicio. Elige periodo y revisa moneda y tratamiento de créditos.
  3. Ejemplo operativo: US$60 para el periodo acordado, con umbrales de gasto real de 25%, 50%, 75% y 100%. Usa ese importe únicamente en USD; en otra moneda acuerda el equivalente con el docente.
  4. Verifica destinatarios y guarda. Registra el responsable y qué revisará cuando llegue un aviso.

Comprueba: presupuesto, alcance, periodo, importe, moneda, destinatarios y umbrales guardados. No esperes un correo instantáneo ni provoques gasto para probarlo.

Si falla: permisos insuficientes → responsable docente; presupuesto existente → comprobarlo antes de crear otro. Si los créditos se descuentan del costo mostrado, documentarlo para interpretar el consumo.

Un presupuesto de alertas no detiene gasto. El importe es un ejemplo, no una cotización ni garantía.

4. Crea el lugar donde conservarás la evidencia · 12 min

Antes: proyecto correcto y región acordada para el curso.

  1. Abre Cloud Storage → Buckets → Crear.
  2. Elige un nombre único, en minúsculas y sin datos personales. Ejemplo de estructura: curso-equipo07-datos-a8f2; cambia el sufijo, no lo copies literalmente.
  3. Selecciona ubicación regional acordada y clase Standard. Mantén una ubicación compatible con el dataset BigQuery que se creará después.
  4. Usa acceso uniforme y prevención de acceso público. Revisa opciones de protección/recuperación y costo antes de guardar; registra las elegidas.
  5. Crea el bucket y copia su URI con formato gs://nombre-del-bucket. Registra también ubicación y proyecto.

Comprueba: el bucket figura en el proyecto correcto y sus detalles coinciden con H1. Puede permanecer vacío hoy.

Si falla: nombre ocupado → elegir otro sufijo; permiso denegado → revisar identidad/proyecto; ubicación incorrecta → consultar al docente antes de cargar datos. No hacer público el bucket para solucionar acceso.

5. Lee el inventario sin confundirlo con un contrato · 10 min

Abre el extracto local del inventario. Proviene del snapshot de metadata.json del Drive del curso, consultado el 5 de noviembre de 2026. No se han descargado los datasets desde esta guía.

  1. Localiza all_data.csv y anota formato, tamaño reportado y URL.
  2. Identifica qué campos del catálogo describen el archivo y qué preguntas no pueden contestar.
  3. Registra tres comprobaciones pendientes antes de analizar: una sobre significado/grano, una sobre fecha/calidad y una sobre procedencia/permiso de uso.

Comprueba: puedes explicar por qué el tamaño de un archivo no revela su número de observaciones ni valida su licencia. La modificación del archivo tampoco prueba actualidad del fenómeno.

Si falla Drive: usa el extracto local. Si no conoces el esquema, escribe «pendiente de perfilado»; no inventes encabezados. La categoría del inventario puede ser genérica y no define el dominio.

6. Dibuja el mapa y sus responsabilidades · 8 min

Completa el mapa de la plantilla H1 sin afirmar que ya se implementaron las capas:

  1. Bronze: original y procedencia. ¿Quién puede recibirlo y qué prueba de recepción conservará?
  2. Silver: reglas y calidad. ¿Quién aprueba una exclusión y cómo se cuenta?
  3. Gold: indicadores y consumidor. ¿Quién define fórmula, unidad y periodo?

Comprueba: cada capa tiene una promesa, evidencia prevista y responsable por función. El mismo equipo puede cubrir varias funciones.

Si no sabes la regla: registra una hipótesis y quién debe confirmarla. No elimines la incertidumbre del diagrama. Las implementaciones Bronze/Silver/Gold ocurrirán en S3–S5.

Transferencia · tu dataset y tu decisión · 30 min

El proyecto final no usa los mismos datos para todos. Cada equipo elige una fuente distinta; el docente verifica duplicados y viabilidad. Un CSV y su Parquet o dos filtros del mismo archivo no cuentan como orígenes distintos.

Candidatas para discutir, no datasets ya certificados

  • Biblioteca: comparar uso histórico de colecciones; distinguir filas de conteos de préstamos.
  • Videojuegos: comparar patrones de reseñas; no inferir ventas o usuarios totales.
  • Ciudad: revisar cobertura y registros por zona; no inferir riesgo poblacional sin denominadores.
  • Finanzas de ejemplo: revisar señales y montos por moneda; no llamarlas fraude confirmado.
  • Catálogo/valoraciones: explorar cobertura y puntuaciones; no construir un recomendador de ML.

La fuente se valida y asigna con el docente antes de terminar S2. Los nombres existen en el inventario, pero falta perfilar contenido, derechos y calidad. Si el número de equipos supera las opciones viables, se ampliará el catálogo antes de asignar.

Persistencia: la ficha editable se guarda solo en este navegador y se descarga como JSON. No reserva datasets ni envía datos a un servidor. No introduzcas secretos. Si guardar localmente falla, descarga la ficha.

Al cerrar

Guarda evidencia sin secretos. El presupuesto y el bucket permanecerán para próximas sesiones. Hoy no se requiere crear una VM ni clúster. Revisa por separado recursos que ya tenías: cerrar una pestaña o Cloud Shell no detiene otros servicios. El docente confirma qué se conserva, detiene o expira.
