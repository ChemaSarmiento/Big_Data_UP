SQL con MariaDB: de una pregunta de negocio a una consulta

Guía para trabajar en tu propio proyecto de Google Cloud. Todas las salidas son resultados reales de la base employees en MariaDB 10.6; tus tiempos pueden variar ligeramente. employees es una base de muestra con datos generados (licencia CC BY-SA 3.0), no una empresa real. Entrar a la VM con gcloud compute ssh se ensayó; conectarte desde un cliente externo (por ejemplo un editor de código) no se ensayó.

Antes de empezar

  • Una VM con MariaDB creada en la sesión 1 (nombre mariadb-curso y zona us-central1-a si usaste los valores por defecto) y encendida.
  • Cloud Shell abierto en tu proyecto.
  • Unos 4 minutos de espera para cargar employees (paso 1) y unos 500 MB libres en el disco de la VM: la base ocupa 367 MB.
  • Usuario big_data_user y contraseña Example123: son credenciales didácticas para datos de práctica; no uses este patrón con datos reales.

Preparación, herramientas y ruta exacta

Ruta: consola de Google Cloud → Cloud Shell → gcloud compute ssh mariadb-curso → terminal de la VM → cliente mysql (mysql -u big_data_user -pExample123 employees). Pega cada bloque de la guía en el cliente interactivo; cada sentencia termina con punto y coma. Si prefieres ejecutar un archivo completo dentro de la VM, usa mysql -u big_data_user -pExample123 employees -t < archivo.sql. Cada paso termina con tres ejercicios y su comprobación numérica. Guarda tus consultas en un archivo propio (por ejemplo mis_consultas.sql).

Paso 1 · Conéctate a tu VM y carga employees · 12 min

Dónde: Consola de Google Cloud → ícono de Cloud Shell (>_) arriba a la derecha. Después, la terminal de tu VM.

Acción: Entra a tu VM con gcloud compute ssh (si cambiaste el nombre o la zona en la sesión 1, usa los tuyos). Dentro de la VM clona el repositorio test_db y carga employees con una sola instrucción. La carga tarda unos 3 a 4 minutos: mientras corre, lee el paso 2. Al terminar, cuenta las filas de cada tabla.

Costo estimado: Sin cargo adicional: solo el cómputo de tu VM encendida (e2-micro). Apagarla al final de la sesión evita ese cargo.

# Paso 1 · Entra a tu VM y carga la base employees.
# Parte A: en Cloud Shell. Si cambiaste el nombre o la zona de la VM en la sesión 1, usa los tuyos.
gcloud compute ssh mariadb-curso --zone=us-central1-a

# Parte B: ya dentro de la VM (el prompt cambia a tu_usuario@mariadb-curso).
git clone --depth 1 https://github.com/datacharmer/test_db.git
cd test_db
time mysql -u big_data_user -pExample123 -t < employees.sql

# Comprobación: cuenta las filas de cada tabla.

SELECT (SELECT COUNT(*) FROM employees)    AS empleados,

       (SELECT COUNT(*) FROM dept_manager) AS dept_manager,

Paso 3 · Filtra y ordena · 12 min

Dónde: Cliente mysql de la VM (el mismo del paso 2).

Acción: Practica WHERE con AND, el efecto de los paréntesis, IN, BETWEEN y LIKE, y luego ORDER BY y LIMIT. Resuelve E1 a E3 del archivo s02_03_filtrar_y_ordenar.sql.

Costo estimado: Sin cargo adicional.

-- Paso 3 · Filtra y ordena.
-- Ejecuta el archivo completo con:
--   mysql -u big_data_user -pExample123 employees -t < s02_03_filtrar_y_ordenar.sql

-- 3.1 WHERE con AND: mujeres contratadas desde 1990. Comprueba: 53839.
SELECT COUNT(*) AS mujeres_desde_1990
FROM employees
WHERE gender = 'F' AND hire_date >= '1990-01-01';

-- 3.2 Los paréntesis cambian la respuesta. Comprueba: 869 y 722.
SELECT COUNT(*) AS sin_parentesis
FROM employees
WHERE gender = 'F' AND hire_date >= '1999-01-01' OR first_name = 'Georgi';

SELECT COUNT(*) AS con_parentesis
FROM employees
WHERE gender = 'F' AND (hire_date >= '1999-01-01' OR first_name = 'Georgi');

-- 3.3 IN, BETWEEN y LIKE. Comprueba: 709, 25610 y 186.
SELECT COUNT(*) AS in_tres_nombres FROM employees WHERE first_name IN ('Georgi', 'Bezalel', 'Parto');
SELECT COUNT(*) AS contratados_1990 FROM employees WHERE hire_date BETWEEN '1990-01-01' AND '1990-12-31';
SELECT COUNT(*) AS apellido_fac     FROM employees WHERE last_name LIKE 'Fac%';

-- 3.4 ORDER BY y LIMIT: los cinco salarios vigentes más altos (to_date = '9999-01-01' significa «hoy»).
SELECT emp_no, salary
FROM salaries
WHERE to_date = '9999-01-01'
ORDER BY salary DESC
LIMIT 5;

-- 3.5 Empates: varias personas entraron el primer día. Una segunda llave fija el orden.
SELECT emp_no, hire_date
FROM employees
ORDER BY hire_date, emp_no
LIMIT 5;

Paso 4 · Resume y agrupa · 12 min

Dónde: Cliente mysql de la VM.

Acción: Usa funciones de agregación, GROUP BY, una función de fecha (YEAR), HAVING y CASE. Observa cómo cambian los números cuando filtras lo vigente. Resuelve E1 a E3 del archivo s02_04_resumir_y_agrupar.sql.

Costo estimado: Sin cargo adicional.

-- Paso 4 · Resume y agrupa.
-- Ejecuta el archivo completo con:
--   mysql -u big_data_user -pExample123 employees -t < s02_04_resumir_y_agrupar.sql

-- 4.1 Funciones de agregación sobre los salarios vigentes. Comprueba: 240124 filas, promedio 72012.
SELECT COUNT(*)       AS vigentes,
       MIN(salary)    AS minimo,
       MAX(salary)    AS maximo,
       ROUND(AVG(salary)) AS promedio,
       SUM(salary)    AS nomina
FROM salaries
WHERE to_date = '9999-01-01';

-- 4.2 El promedio de todo el historial no es el salario de hoy. Comprueba: 63811.
SELECT ROUND(AVG(salary)) AS promedio_del_historial FROM salaries;

-- 4.3 GROUP BY: cuántas personas hay de cada género. Comprueba: M 179973 y F 120051.
SELECT gender, COUNT(*) AS empleados
FROM employees
GROUP BY gender;

-- 4.4 Una función de fecha para agrupar: contrataciones por año.
SELECT YEAR(hire_date) AS anio, COUNT(*) AS contratados
FROM employees
GROUP BY YEAR(hire_date)
ORDER BY anio;

-- 4.5 HAVING filtra grupos; WHERE filtra filas. Comprueba: d005 61386, d004 53304 y d007 37701.
SELECT dept_no, COUNT(*) AS vigentes
FROM dept_emp
WHERE to_date = '9999-01-01'
GROUP BY dept_no
HAVING COUNT(*) > 30000
ORDER BY vigentes DESC;

-- 4.6 CASE: una regla de negocio convertida en columna (bandas de salario vigente).
SELECT CASE WHEN salary < 50000  THEN '1 · menos de 50 mil'
            WHEN salary < 70000  THEN '2 · 50 a 70 mil'
            WHEN salary < 100000 THEN '3 · 70 a 100 mil'
            ELSE                      '4 · 100 mil o más' END AS banda,
       COUNT(*) AS empleados
FROM salaries
WHERE to_date = '9999-01-01'
GROUP BY banda
ORDER BY banda;

Paso 5 · Une tablas con JOIN · 12 min

Dónde: Cliente mysql de la VM.

Acción: Une employees con dept_emp y departments; compara INNER con LEFT; comprueba que un JOIN puede multiplicar filas y que un JOIN sin condición cruza todo con todo. Resuelve E1 a E3 de s02_05_unir_tablas.sql.

Costo estimado: Sin cargo adicional. El conteo del cruce (2,700,216 filas) solo cuenta; no lo imprimas con SELECT *.

-- Paso 5 · Une tablas con JOIN.
-- Ejecuta el archivo completo con:
--   mysql -u big_data_user -pExample123 employees -t < s02_05_unir_tablas.sql

-- 5.1 Tres tablas unidas por sus llaves: empleado → departamento → nombre del departamento.
SELECT e.emp_no, e.first_name, e.last_name, d.dept_name, de.from_date, de.to_date
FROM employees AS e
JOIN dept_emp AS de ON de.emp_no = e.emp_no
JOIN departments AS d ON d.dept_no = de.dept_no
WHERE e.emp_no IN (10001, 10010)
ORDER BY e.emp_no, de.from_date;

-- 5.2 INNER JOIN solo conserva a quien tiene pareja. Comprueba: 24 personas son gerentes.
SELECT COUNT(*) AS con_pareja
FROM employees AS e
JOIN dept_manager AS m ON m.emp_no = e.emp_no;

-- 5.3 LEFT JOIN conserva todas las filas de la izquierda y pone NULL donde no hay pareja.
--     Comprueba: 300024 filas, 24 con gerencia y 300000 sin gerencia.
SELECT COUNT(*) AS filas,
       COUNT(m.emp_no) AS con_gerencia,
       COUNT(*) - COUNT(m.emp_no) AS sin_gerencia
FROM employees AS e
LEFT JOIN dept_manager AS m ON m.emp_no = e.emp_no;

SELECT e.emp_no, e.first_name, e.last_name, m.dept_no
FROM employees AS e
LEFT JOIN dept_manager AS m ON m.emp_no = e.emp_no
WHERE e.emp_no IN (10001, 10002, 10003, 110022, 110039, 110085)
ORDER BY e.emp_no;

-- 5.4 Un JOIN puede multiplicar filas. Una persona con 17 salarios se vuelve 17 filas.
--     Comprueba: 2844047 filas (no 300024) y promedio 63811 (no 72012).
SELECT COUNT(*) AS filas, ROUND(AVG(s.salary)) AS promedio
FROM employees AS e
JOIN salaries AS s ON s.emp_no = e.emp_no;

-- 5.5 Unir solo lo vigente evita la multiplicación. Comprueba: 240124 filas y promedio 72012.
SELECT COUNT(*) AS filas, ROUND(AVG(s.salary)) AS promedio_vigente
FROM employees AS e
JOIN salaries AS s ON s.emp_no = e.emp_no AND s.to_date = '9999-01-01';

-- 5.6 Un JOIN sin condición cruza todo con todo. Comprueba: 2700216 filas (300024 × 9).
SELECT COUNT(*) AS cruce FROM employees CROSS JOIN departments;

Paso 6 · De la pregunta de negocio a la consulta · 12 min

Dónde: Cliente mysql de la VM.

Acción: Prueba subconsultas y resuelve tres preguntas de negocio con el método de la clase: primero la pregunta, luego las piezas y al final la consulta. Termina con los límites del dato. Resuelve E1 a E3 de s02_06_de_la_pregunta_a_la_consulta.sql.

Costo estimado: Sin cargo adicional. Al terminar la sesión, apaga la VM (ver cierre).

-- Paso 6 · De la pregunta de negocio a la consulta.
-- Ejecuta el archivo completo con:
--   mysql -u big_data_user -pExample123 employees -t < s02_06_de_la_pregunta_a_la_consulta.sql
-- Regla: escribe primero la pregunta, luego las piezas (qué columnas, de qué tabla, qué filas, qué grupos),
-- y solo al final la consulta.

-- 6.1 Subconsulta escalar: ¿cuántas personas ganan hoy más que el promedio de hoy? Comprueba: 107706.
SELECT COUNT(*) AS arriba_del_promedio
FROM salaries
WHERE to_date = '9999-01-01'
  AND salary > (SELECT AVG(salary) FROM salaries WHERE to_date = '9999-01-01');

-- 6.2 Subconsulta con IN: nombres de personas que han sido gerentes (24 en total; aquí cinco).
SELECT first_name, last_name
FROM employees
WHERE emp_no IN (SELECT emp_no FROM dept_manager)
ORDER BY last_name
LIMIT 5;

-- 6.3 Pregunta A: ¿cuántas personas trabajan hoy en la empresa? Comprueba: 240124 (y no 300024).
SELECT COUNT(DISTINCT emp_no) AS trabajan_hoy
FROM dept_emp
WHERE to_date = '9999-01-01';

-- 6.4 Pregunta B: ¿qué departamentos tienen más de 30,000 personas hoy? (nombre, no código)
SELECT d.dept_name, COUNT(*) AS vigentes
FROM dept_emp AS de
JOIN departments AS d ON d.dept_no = de.dept_no
WHERE de.to_date = '9999-01-01'
GROUP BY d.dept_name
HAVING COUNT(*) > 30000
ORDER BY vigentes DESC;

-- 6.5 Pregunta C: ¿hay diferencia de salario vigente promedio entre géneros? Comprueba: M 72045 y F 71964.
--     Qué NO demuestra: que el pago sea justo o injusto; la consulta no mira puesto, antigüedad ni historia.
SELECT e.gender, COUNT(*) AS vigentes, ROUND(AVG(s.salary)) AS salario_promedio
FROM employees AS e
JOIN salaries AS s ON s.emp_no = e.emp_no AND s.to_date = '9999-01-01'
GROUP BY e.gender;

-- 6.6 Hasta dónde llega el dato. Comprueba: última contratación 2000-01-28 y último cambio de salario 2002-08-01.
SELECT (SELECT MAX(hire_date)  FROM employees) AS ultima_contratacion,
       (SELECT MAX(from_date)  FROM salaries)  AS ultimo_cambio_de_salario;

-- 4.6 CASE: una regla de negocio convertida en columna (bandas de salario vigente).
SELECT CASE WHEN salary < 50000  THEN '1 · menos de 50 mil'
            WHEN salary < 70000  THEN '2 · 50 a 70 mil'
            WHEN salary < 100000 THEN '3 · 70 a 100 mil'
            ELSE                      '4 · 100 mil o más' END AS banda,
       COUNT(*) AS empleados
FROM salaries
WHERE to_date = '9999-01-01'
GROUP BY banda
ORDER BY banda;

-- 5.1 Tres tablas unidas por sus llaves: empleado → departamento → nombre del departamento.
SELECT e.emp_no, e.first_name, e.last_name, d.dept_name, de.from_date, de.to_date
FROM employees AS e
JOIN dept_emp AS de ON de.emp_no = e.emp_no
JOIN departments AS d ON d.dept_no = de.dept_no
WHERE e.emp_no IN (10001, 10010)
ORDER BY e.emp_no, de.from_date;

-- 5.2 INNER JOIN solo conserva a quien tiene pareja. Comprueba: 24 personas son gerentes.
SELECT COUNT(*) AS con_pareja
FROM employees AS e
JOIN dept_manager AS m ON m.emp_no = e.emp_no;

-- 5.3 LEFT JOIN conserva todas las filas de la izquierda y pone NULL donde no hay pareja.
--     Comprueba: 300024 filas, 24 con gerencia y 300000 sin gerencia.
SELECT COUNT(*) AS filas,

       COUNT(*) - COUNT(m.emp_no) AS sin_gerencia
FROM employees AS e
LEFT JOIN dept_manager AS m ON m.emp_no = e.emp_no;

WHERE e.emp_no IN (10001, 10002, 10003, 110022, 110039, 110085)

-- 6.1 Subconsulta escalar: ¿cuántas personas ganan hoy más que el promedio de hoy? Comprueba: 107706.
SELECT COUNT(*) AS arriba_del_promedio
FROM salaries
WHERE to_date = '9999-01-01'
  AND salary > (SELECT AVG(salary) FROM salaries WHERE to_date = '9999-01-01');

-- 6.2 Subconsulta con IN: nombres de personas que han sido gerentes (24 en total; aquí cinco).
SELECT first_name, last_name
FROM employees
WHERE emp_no IN (SELECT emp_no FROM dept_manager)
ORDER BY last_name
LIMIT 5;

-- 6.3 Pregunta A: ¿cuántas personas trabajan hoy en la empresa? Comprueba: 240124 (y no 300024).
SELECT COUNT(DISTINCT emp_no) AS trabajan_hoy
FROM dept_emp
WHERE to_date = '9999-01-01';

-- 6.4 Pregunta B: ¿qué departamentos tienen más de 30,000 personas hoy? (nombre, no código)
SELECT d.dept_name, COUNT(*) AS vigentes
FROM dept_emp AS de
JOIN departments AS d ON d.dept_no = de.dept_no
WHERE de.to_date = '9999-01-01'
GROUP BY d.dept_name
HAVING COUNT(*) > 30000
ORDER BY vigentes DESC;

-- 6.5 Pregunta C: ¿hay diferencia de salario vigente promedio entre géneros? Comprueba: M 72045 y F 71964.
--     Qué NO demuestra: que el pago sea justo o injusto; la consulta no mira puesto, antigüedad ni historia.
SELECT e.gender, COUNT(*) AS vigentes, ROUND(AVG(s.salary)) AS salario_promedio
FROM employees AS e
JOIN salaries AS s ON s.emp_no = e.emp_no AND s.to_date = '9999-01-01'
GROUP BY e.gender;

-- 6.6 Hasta dónde llega el dato. Comprueba: última contratación 2000-01-28 y último cambio de salario 2002-08-01.
SELECT (SELECT MAX(hire_date)  FROM employees) AS ultima_contratacion,
       (SELECT MAX(from_date)  FROM salaries)  AS ultimo_cambio_de_salario;
