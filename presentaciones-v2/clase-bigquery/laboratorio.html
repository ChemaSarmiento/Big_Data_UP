Laboratorio · all_data.csv en BigQuery

Laboratorio ejecutivo · 80 minutos. Tres etapas y tres archivos SQL. En cada paso: abrir, copiar y ejecutar una consulta.

Antes de empezar

El docente prepara emergent_bronze, emergent_silver y emergent_gold en el proyecto de práctica. Así el grupo empieza mirando Bronze. Para cargar durante clase, sube all_data_muestra.csv como CSV en emergent_bronze.entrada, con las 15 columnas STRING de esquema-bronze.json. La muestra tiene 4500 filas.

En Google Cloud: BigQuery → SQL workspace → Nueva consulta. Copia el bloque numerado y pulsa Ejecutar. El docente prepara el proyecto, permisos y facturación. No hace falta configurar la cuenta durante el laboratorio.

El archivo original pesa más de 20 GB. El docente lo prepara previamente en GCS; el grupo usa la muestra.

Paso 1 · Bronze · ver lo que llegó · 20 min

Abre BigQuery Studio → SQL workspace → Nueva consulta. Carga all_data_muestra.csv en emergente_bronze.entrada con el esquema incluido: 15 columnas STRING, formato CSV y una fila de cabecera. Ejecuta estas consultas. Compara el valor original TLALPAN con municipio_limpio. Bronze conserva la entrada; todavía no corrige sus valores.

Comprueba: 4500 filas. municipio conserva espacios finales y fechaRegistro mantiene fecha y hora.

Si no coincide: Revisa delimitador coma, UTF-8, cabecera y comillas. No uses autodetección: las columnas crudas se guardan como STRING.

-- Bronze muestra los valores como llegaron desde el CSV.
-- Carga previa: all_data_muestra.csv en emergente_bronze.entrada.
SELECT producto, presentacion, marca, precio, fechaRegistro, municipio
FROM emergente_bronze.entrada
WHERE producto='REFRESCO' AND marca='SPRITE' AND municipio LIKE 'TLALPAN%'
LIMIT 10;

-- La limpieza se muestra como una consulta; la tabla original no cambia.
SELECT municipio AS municipio_original, TRIM(municipio) AS municipio_limpio,
 precio AS precio_original, SAFE_CAST(precio AS NUMERIC) AS precio_numerico
FROM emergente_bronze.entrada
WHERE producto='REFRESCO' AND marca='SPRITE' AND TRIM(municipio)='TLALPAN'
LIMIT 5;

SELECT COUNT(*) AS filas_bronze FROM emergente_bronze.entrada;
-- Esperado con la muestra: 4500.

Paso 2 · Silver · limpiar y tipar · 30 min

Abre otra consulta y ejecuta los bloques numerados en orden. El primero crea una tabla limpia. El segundo guarda aparte los registros que no se pueden usar. El tercero compara conteos. TRIM quita espacios y SAFE_CAST convierte precio y fecha sin modificar Bronze. En la muestra no esperamos rechazos; la regla queda preparada para cuando aparezcan.

Comprueba: 4500 filas aceptadas; 0 rechazadas con estas reglas. TLALPAN ya no tiene espacios y precio es NUMERIC.

Si no coincide: Si SAFE_CAST devuelve NULL, busca la fila rechazada y lee el motivo. Conserva la regla; revisa el valor original en Bronze.

20_silver.sql ↓

Ver consultas
-- 1. Crear Silver con nombres limpios y tipos útiles. Bronze queda intacta.
CREATE OR REPLACE TABLE emergente_silver.precios_limpios AS
SELECT TRIM(producto) AS producto, TRIM(presentacion) AS presentacion,
 TRIM(marca) AS marca, TRIM(categoria) AS categoria,
 SAFE_CAST(precio AS NUMERIC) AS precio_mxn,
 SAFE_CAST(fechaRegistro AS DATE) AS fecha,
 TRIM(cadenaComercial) AS cadena_comercial,
 TRIM(nombreComercial) AS establecimiento,
 TRIM(estado) AS estado, TRIM(municipio) AS municipio,
 SAFE_CAST(latitud AS FLOAT64) AS latitud,
 SAFE_CAST(longitud AS FLOAT64) AS longitud
FROM emergente_bronze.entrada;

-- 2. Separar los registros que requieren revisión.
CREATE OR REPLACE TABLE emergente_silver.precios_para_revisar AS
SELECT * FROM emergente_silver.precios_limpios
WHERE producto IS NULL OR marca IS NULL OR presentacion IS NULL
 OR precio_mxn IS NULL OR precio_mxn<=0 OR fecha IS NULL;

-- 3. Revisar el conteo. Con la muestra: 4500 Silver y 0 para revisar.
SELECT (SELECT COUNT(*) FROM emergente_bronze.entrada) AS bronze,
 (SELECT COUNT(*) FROM emergente_silver.precios_limpios) AS silver,
 (SELECT COUNT(*) FROM emergente_silver.precios_para_revisar) AS revisar;

Paso 3 · Gold · preparar una comparación · 30 min

Abre otra consulta y ejecuta los bloques numerados. Gold agrupa el precio por producto, marca, presentación, fecha y tienda. Después muestra el caso Sprite del 19 de marzo de 2014 en Tlalpan. Revisa cuántas tiendas aparecen: la comparación cubre las observaciones de esta muestra.

Comprueba: Dos establecimientos observados: 15.10 y 15.50 MXN. Diferencia: 0.40 MXN. Evidencia histórica de la muestra.

Si no coincide: Si no aparecen dos filas, revisa fecha, producto, marca, presentación y municipio.

Ver consultas
-- Gold: precio por tienda para un producto, presentación y fecha.
CREATE OR REPLACE TABLE emergente_gold.precio_sprite_tlalpan AS
SELECT fecha, estado, municipio, producto, marca, presentacion,
 cadena_comercial, establecimiento, MIN(precio_mxn) AS precio_mxn,
 COUNT(*) AS observaciones
FROM emergente_silver.precios_limpios
WHERE fecha=DATE '2014-03-19' AND producto='REFRESCO' AND marca='SPRITE'
 AND presentacion='BOTELLA 2 LT. NO RETORNABLE'
 AND estado='DISTRITO FEDERAL' AND municipio='TLALPAN'
GROUP BY fecha, estado, municipio, producto, marca, presentacion,
 cadena_comercial, establecimiento;

-- Muestra: dos tiendas observadas; 15.10 y 15.50 MXN.
SELECT establecimiento, precio_mxn, observaciones
FROM emergente_gold.precio_sprite_tlalpan ORDER BY precio_mxn;
-- Evidencia histórica. No prueba existencia ni precio actual.

Ruta docente para el archivo completo

Conservar el original en un bucket autorizado, con nombre deobjeto, tamaño, generación/checksum y manifiesto. Transferir desde una estación o entorno con espacio suficiente; no usar el disco limitado deCloud Shell. Ejecutar cargar-gcs.sh con una URIgs:// concreta ya preparada. Se escribe solo emergente_bronze.entrada. Antes de01, cambiar lote y fuente a los del archivo completo. Perfilar02 y verificar fechas antes de reconstruir Silver/Gold. Ejecutar una vez, guardar controles y usar tablas preparadas en clase. El diseño no presupone que la muestra valide todas las filas del archivo.

Para optimizar: selecciona las columnas necesarias, filtra por fecha y revisa el estimado de bytes antes de ejecutar. LIMIT limita las filas de salida; no necesariamente los datos leídos. Con el archivo completo, el docente ensaya y comparte los resultados.
